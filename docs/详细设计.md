# 系统详细设计

本文档涵盖了目前系统已规划和实现的核心业务模块的详细设计。相关数据库建表脚本统一维护在 `docs/项目所有表结构.sql` 中。

---

## 模块一：用户管理模块

### 1. 需求概述
- 提供系统基础的访问控制与多用户隔离机制。
- 确保只有处于登录状态的用户才能访问业务系统，并强制要求各个业务数据模块按登录用户的 ID 进行数据隔离。

### 2. 数据库设计方案
- 涉及核心表：**`sys_user`（系统用户表）**
- 字段包含：主键 `id`、用户名 `username`（系统内唯一）、密码 `password`、帐号状态 `status`（1正常，0禁用）。

### 3. 核心功能与安全交互逻辑
1. **用户认证与状态保持**：
   - 接收前端传入的用户名和密码，利用基础设施层的 Repository 模块查询匹配。
   - 验证通过后，将用户信息（如 `user_id`）写入服务端 Session 以维持登录状态。
   - **登录后原路跳转**：前端登录页面在成功登录后，会自动解析 URL 里的 `redirect` 参数。如果该参数存在，并且符合站内相对路径的安全正则规范（以单斜杠 `/` 开头且不以双斜杠或反斜杠开头，以防御 Open Redirect 漏洞），则跳转回原本请求的资源页面，否则默认跳转到系统主页 `./`。
   - **会话生命周期与长期免登**：服务端 Session 有效期与客户端 `JSESSIONID` Cookie 生命周期统一配置为 **7 天（`7d`）**。在保证用户连续 7 天无操作前保持登录态的同时，即使关闭浏览器重新打开也能自动保持登录，免去频繁重复登录。
2. **全局安全拦截（LoginFilter）**：
   - 拦截除登录接口、静态资源扩展名白名单（如 `.css`, `.js`, `.png` 等多媒体/样式/脚本文件，排除 `/api/` 路径）外的所有请求，支持各业务子模块（如 `/inv/js/`, `/inv/css/`）静态资源的正常加载。对于未登录页面请求重定向至登录页并携带 `redirect` 参数以保留原请求路径，非页面类 API 请求则直接返回 401 JSON 错误响应。
   - **页面防缓存与状态失效控制**：针对 HTML 页面及未登录重定向响应增加 `Cache-Control: no-cache, no-store, must-revalidate` 标头，杜绝浏览器因读取旧 HTML 强缓存而绕过服务端鉴权或造成界面卡滞。
   - **防路径穿越机制**：对请求 URI 进行严格的规范化处理（Canonical Path Validation），识别并拦截包含 `..`, `//`, `;` 等异常字符的路径，杜绝恶意读取或越权访问服务器内部资源。
3. **架构隔离设计（Repository 模式）**：
   - 在 `cyc-infra` 层定义 `SysUserRepository` 接口并提供实现，彻底隔离 MyBatis 的 `SysUserMapper` 组件，禁止 `cyc-service` 业务逻辑层直接与底层 SQL 映射器耦合。

## 模块二：投资记录管理模块

### 1. 需求概述
旨在提供一个轻量级的**个人投资记录管理系统**，满足以下核心需求：
- **资产分类管理**：支持将投资产品分类（如基金、股票、ETF、固定收益类）。
- **资金流水记录**：追踪具体的投资行为（买入、追加投入、卖出等），并详细记录每次的金额、单价、份额与时间。
- **汇率与货币管理**：记录跨币种投资产生的换汇流水（支持 CNY/HKD/USD/EUR/GBP/USDT 等）。纯记录性质，无严格账户余额约束。
- **收益追踪**：支持记录与查看特定产品的累计收益和单日收益。收益由用户手动录入，前端支持联动计算。
- **多用户强隔离**：所有投资及流水数据均绑定 `user_id`，杜绝越权访问他人账单。

### 2. 数据库设计方案
涉及 5 张核心业务表，字段均包含 `user_id` 以作鉴权隔离：
1. **`inv_product`（投资标的表）**：记录产品名称、代码、分类及计价币种。
   - **设计细节**：`type`（分类）字段采用 `VARCHAR(20)` 类型，直接映射后端的 `ProductTypeEnum` 枚举（如 `FUND`, `STOCK`），避免魔数，便于代码统一维护；计价与交易币种统一由后端 `CurrencyEnum` 单点枚举驱动，新增币种只需在该枚举追加一行，全站下拉框与筛选控制台自动无缝接入。
   - **持仓与收益指标物化抽取（v1.2 架构重构）**：将以往每次查询时在内存中动态回放的指标正式抽取持久化至物理表中。经严谨论证，物理表最终保留 6 个不可替代的核心关键字段：当期剩余持仓份额与成本（`remaining_shares`, `cost_amount`）、最新市值（`market_value`）、当期已实现收益（`realized_profit`）、分段盈亏明细（`realized_profit_text`）、持有时长文本（`hold_duration_text`）。其中：
     - `remaining_shares` 记录当期剩余持仓份额（股票/基金通用，清仓后为 0）；
     - `cost_amount` 在领域模型上实现全资产大一统（股票/ETF通过交易流水自动推算在仓成本，清仓为 0；普通理财/存款通过最新快照自动同步在仓本金，原冗余字段 `principal` 彻底废除并由其完全承载）；
     - `market_value` 记录标的当期最新市值（清仓为 0，持有中同步最新快照市值或在仓成本，直接供前台卡片 O(1) 毫秒级极速渲染）；
     - `realized_profit` 统一承载标的当期周期的收益指标（股票持仓中优先同步最新快照的累计总收益，使卡片真实反映股价涨跌带来的当期浮盈；若暂无快照则以流水已落袋盈亏保底；股票清仓后则为最后一次建仓周期的结转收益，如苹果的 `35.00`；普通理财中为最新快照累计总收益）；
     - `realized_profit_text` 优雅记录各轮周期的明细分段（如 `31.59 | 35.00`），与持有时长（`20天 | 45天`）深度呼应；
     - `hold_duration_text` 记录各周期的持有天数展示文本。
     其余衍生或过程字段（如当日收益 `daily_profit`、最新快照日期 `latest_snapshot_date`、清仓状态 `is_cleared`、成本均价 `cost_price`、流水边界日期与累计天数）无需物理列冗余，统一由实体类内存动态计算与派生。彻底消除列表查询时的 N+1 级联扫描，使前台列表查询变为极速的单表 O(1) 读取。命名全面去除 `stock_` 前缀，适用于股票、基金、ETF、理财、黄金等全品类投资标的。
2. **`inv_record`（交易流水表）**：记录每一笔买入/卖出的金额、单价、份额及手续费等。
   - **设计细节**：引入 `value_date` (起息日/确认日) 字段，支持“T+N 确认机制”。分离交易扣款时间与起息时间，用以识别“在途资金”。
3. **`inv_exchange`（换汇记录表）**：跨币种划转纯流水账记录。
   - **设计细节**：支持**双向汇率存储**，包含 `exchange_rate` (买入/卖出) 和 `exchange_rate_reverse` (卖出/买入) 两个字段；新增 `tag`（业务标签）字段，支持枚举范围【换汇、提取、损耗、消费】。
4. **`inv_profit_snapshot`（收益快照表）**：记录用户手动录入或前端计算的累计收益与单日收益。
5. **`inv_exchange_memo`（外汇对账备忘录表）**：独立于常规流水外，提供专用的长文本字段，用以记录阶段性资金对账与复盘节点。

### 3. 核心功能与前端交互逻辑
1. **标的管理模块**
   - 新增/编辑产品信息，支持数据回显。
   - 列表查询、分类筛选以及产品删除功能（带后端数据归属鉴权防覆盖机制）。
   - 标的在列表和详情展示时，币种徽章样式（包括背景色、文字色、边框色）完全由后端 `CurrencyEnum` 集中维护并通过字典接口动态下发内联样式，前端 CSS 与 JS 彻底移除了任何币种名称与样式类的硬编码，实现真正意义上的单点全链路自适应。
   - **产品指标事件驱动重算引擎（`syncProductMetrics`）**：建立以交易流水表为唯一事实源（SSOT）的单标的重算引擎。当任意交易流水或收益快照发生新增、编辑、删除时，在后端事务后自动触发对应标的的指标全时序重演，并将最终持仓、市值、累计收益与持有周期持久化回写入 `inv_product`。
   - **存量历史标的静默自愈机制**：在产品列表查询接口（`getList`）中内置自愈检测，若识别到历史未初始化的存量标的，自动在毫秒级内静默触发一次全量初始化对账，前台无感且数据 100% 准确；同时提供 `/api/inv/product/sync-all` 显式全量对账接口。
2. **交易流水模块**
   - 针对某个特定标的，录入买入或卖出记录，**同时支持流水的修改与删除操作**。
   - **在途资金与起息控制**：支持灵活配置起息日（默认同交易日），前端双行并列展示。用户在录入收益快照前，可藉此清晰分辨资金是否处于“在途”状态，进而精准剥离未起息资金，防止收益率计算失真。
   - **防空覆盖安全机制**：在执行流水修改（Update）时，后端服务层自动核对权限，并强制继承原有的 `user_id`、`product_id` 和 `create_time` 等底层核心元数据，杜绝更新过程中发生的字段覆盖或丢失风险。
   - **流水备注列展示与表单回显**：打通 `inv_record` 底层 `remark` 字段，交易流水表格新增“备注”独立展示列（支持 XSS 转义防御，空值渲染占位符 `-`）；同时在“记一笔交易”弹窗表单中接入备注选填项，支持新增保存、二次编辑回显与修改落库。
   - **股票持仓与已实现盈亏推演（服务端统一引擎）**：针对股票类标的，服务端依据交易流水按时间时序自动推演当前持仓与已实现盈亏：
     - 买入操作（首次/追加）：增加持仓份额与持仓总成本（包含买入手续费）。
     - 卖出操作：按当前持仓加权平均成本核减成本与份额，差额扣除卖出手续费后计入已实现盈亏。
     - 分红派息：直接计入已实现盈亏，金额严格扣除对应手续费及税费（即净收益 `amount - fee`）。
     - 清仓结算与口径对齐：当剩余持仓份额归零时，残余微小成本尾差自动结算结转至已实现盈亏，标记 `is_cleared = 1`；**市值强制归零为 0.00，累计收益严格对齐最终已实现盈亏**，彻底消除了旧快照导致的口径割裂。
3. **资金记录管理模块（原外汇记录管理）**
   - 独立录入资金/外汇记录，仅作流水账功能。
   - 支持编辑与删除流水的双向操作。
   - **双向汇率自动推演与手动编辑联动**：前端动态监听“买入金额”和“卖出金额”，实时自动推算出**“买入/卖出”**与**“卖出/买入”**双向汇率并填入表单；同时汇率输入框完全支持用户手动编辑与微调，在手动输入任一方向汇率时前端会自动联动计算出反向倒数汇率；列表页也同步直观地展示该双向汇率数据。
   - **业务标签统一配置中心与差异化徽章展示**：在后端 `ExchangeTagEnum` 枚举设立了资金记录业务标签统一配置中心，将标签的 `code`、展示名 `desc`、徽章主题色 `color` 与图标 `icon` 集中单点管理并通过 `/api/inv/dict/all` 全局字典接口下发至前端。新增/编辑弹窗的下拉选项、列表徽章渲染以及顶部筛选栏胶囊均由后端统一动态驱动。未来若需扩展或调整标签，**仅需在 `ExchangeTagEnum` 枚举中追加一行**，全站即自动完成联动适配。目前已预设【换汇（主题蓝）、提取（暖橙）、损耗（次要灰）、消费（青蓝）】等类型。
   - **多币种流转动态汇总与可控排序**：通过前端轻量级计算实现各币种资金的“流入（+）”与“流出（-）”统计，利用金融红绿配色方案及极简符号直观呈现在流水账面板顶部。结余卡片支持用户自定义排序并同步持久化到数据库偏好设置；为了避免日常查阅时误触导致卡片乱位，交互上对齐“我的投资组合”模块，增设显式的“排序/完成”切换按钮，默认锁定拖拽，仅在点击“排序”按钮进入排序模式后方可拖动调整顺序并完成保存。
   - **附加信息记录**：全面启用并打通底层已设计好的 `remark` 字段，允许在前端录入和列表视图中直观地补充、查看换汇相关的附加信息（如地点、用途等）。
   - **卖出、买入与业务标签三维独立筛选控制**：在交易流水表格上方集成了毛玻璃质感的 Filter Chips 筛选控制台，将筛选维度细分为**卖出币种**（红色系标识）、**买入币种**（绿色系标识）与**记录标签**（蓝色系标识）三个独立行；各自支持多选与单行“全部”快捷重置，并联动执行三维交叉联合过滤；右上角提供“重置筛选”一键清空与条数动态统计徽章，纯前端即时响应渲染，极大增强精细化对账检索体验。
   - **独立阶段性资金对账备忘录**：在外汇记录管理模块中新增并集成了一个完全独立的“资金对账备忘录”体系（涉及独立数据库表 `inv_exchange_memo`）。专门用于隔离于具体交易流水之外的长文本大段落资金复盘（如记录特定时间节点的银行卡余额与盈亏）。支持列表拉取、多行文本编辑、删除等完整的增删查改逻辑；前端交互上摒弃了占用空间的底部平铺设计，改用极简的**按钮 Toggle 动态渲染机制**，将卡片列表隐藏收纳于顶部概览区的右侧，点击缩略图按钮即可实现右分栏的就地无缝展开与折叠，并以优雅的单栏瀑布流倒序展示；此外，整个外汇模块所有的核心提交操作（包含“新增换汇保存落库”以及“保存备忘录”）均统一深度接入了防抖防连点的“加载中 (Spinner) 转圈”交互特效，在极大提升操作质感的同时根绝了网络延迟导致的重复提交问题。
4. 收益视图与录入交互（非连续记账处理与股票时序推演）
   - **前端自动计算逻辑（基于 T-1 数据）**：
     - 当用户录入“累计收益”时：系统查找**前一天（T-1）的快照值**，自动计算并带出“当日收益”（当次累计收益 - 前一天累计收益）。
     - 当用户录入“当日收益”时：系统查找**前一天（T-1）的快照值**，自动计算并带出“累计收益”（前一天累计收益 + 当日收益）。
     - **断层处理与连续记账日严格判定（`isContinuousSnapshotDate`）**：系统会动态比对当前录入日期是否恰好为上一笔历史快照日期的相邻自然日（`diffDays === 1`）。若相差超过 1 个自然日（包含周五至周一跨周末相隔 3 天），系统一律严格判定为**断层**：
       - **单日收益不强推**：断层时单日收益输入框保持为空（杜绝将跨期多天累计变动强塞入单日），下方状态标注为“断层未推算”；
       - **手动输入免覆盖**：用户可依据券商真实账单自主手动填入真实的单日收益；在断层状态下，手动修改累计收益或单日收益时**互不联动覆盖**，确保数据独立精准；
       - **基准提示透明化**：弹窗顶部基准提示栏实时呈现断层警告徽章（`断层：单日收益不自动推算`），彻底规避歧义。
   - **在投本金与市值智能推演（加权平均成本与股票隔离机制）**：
     - 在快照录入弹窗中，系统根据当前快照日期自动时序回放截至该日期的交易流水，智能推演“当前累计本金（`principal`）”与“当日市值（`market_value`）”：
     - **买入交易（首次买入1 / 追加买入2）**：累加持仓份额与本金成本（含手续费）；若流水未填写份额，隐式默认按“单价 1.00，份额 = 金额”代入运算。
     - **卖出赎回（3）**：按持仓加权平均成本（在投本金 / 剩余份额）精准核减本金成本；当剩余持仓份额清零（$\le 0.0001$）时，在投本金强制清零归零（0.00），并加设非负保护，从根本上根绝了盈利全额赎回导致本金变负数、以及割肉清仓导致僵尸本金残留的业务痛点。
     - **分红派息（4）**：明确界定为纯收益现金分派，推演过程中严格独立隔离，绝不扣减在投本金，也不改变持仓份额。
     - **当日市值联动与股票隔离保护**：普通理财标的遵循 $\text{当日市值} = \text{在投本金} + \text{累计收益}$；对于**股票类标的（`STOCK`）**，其累计收益包含落袋的已实现盈亏，市值完全由“输入股价 $\times$ 该日期时序持仓份额”唯一决定，系统在用户切换日期重算本金时严格实施**股票市值防篡改隔离**，严禁用普通理财的本金公式覆盖股票市值。
   - **股票收益快照专属时序推演引擎（`updateStockSnapshotCalculation`）**：
     - **历史时序持仓回放（`calculateStockPositionAtDate`）**：针对补录或二次编辑历史快照场景，系统根据所选快照日期回溯历史流水，精确推演出该历史日期的剩余持仓份额、持仓总成本及已实现盈亏，彻底杜绝拿最新当前份额去乘历史股价导致的“时空穿越”失真。编辑历史快照时，亦根据快照当天的实际份额精确反推历史单价回显。
     - **实时指标微仪表盘化与直接微调机制（Financial KPI Dashboard & Editable Inputs）**：股票模式在弹窗中采用三栏金融微卡片布局，将“当日市值”、“累计收益”、“单日收益”对称排布，**这三个推算字段完全支持用户直接手动打字修改**：
       - 输入最新价时，系统自动推算数值并实时填充至这三个输入框中，并自适应应用红绿涨跌字体颜色；累计收益默认推算口径精准对齐**当期在仓浮动盈亏（$\text{当日市值} - \text{在仓总成本}$）**，不再叠加历史旧周期的已结盈亏，同时在下方标签清晰提示当前浮盈与成本基准；
       - 若用户有除息除权、券商杂费微调等特殊诉求，可直接点击任意输入框进行修改；在连续记账日下修改累计收益或单日收益时自动联动计算另一项，在断层日下互不干扰；
       - 保存落库时，系统优先提取用户最新编辑的数值入库，兼具自动推算的高效与手动修正的灵活性。
     - **币种符号动态适配**：输入框前缀根据标的币种动态适配（`$`、`¥`、`HK$`、`€` 等），根绝多币种场景下的硬编码问题。
     - **历史快照表格展示增强**：历史快照表格中累计收益与单日收益全面支持显式正号（`+`）与金融红绿涨跌配色；针对股票标的，仅在快照当时存在有效持仓与市值（`shares > 0 && mv > 0`）时，在“当日市值”列下方智能附带展示当时的推算单价与持仓份额（如 `@ $96.00 (10股)`）；无持仓或市值为 0 时纯净呈现标准市值数值，彻底去除冗余的“已清仓”字样，界面更清爽。
     - **清仓零份额状态防护**：在检测到该日期持仓已清零（$\le 0.0001$ 股）时，展示清仓警告并自动锁定市值（0.00）与收益（已实现盈亏）。
    - **批量快速录入与变动高亮机制**：支持对选定产品在同一弹窗中进行批量快速录入。为了极致优化输入体验，输入框保持空白，免去用户每次退格清空旧值的繁琐操作；同时，每个输入框右侧附加了小巧的“旧: XX”字样的输入组标签（Input Group Text）以直观呈示上期快照值。前端动态监听输入事件并比对输入值与该卡片所绑定的初始快照备份值的差异：默认展示灰色的“不更新”状态标签，一旦检测到任意字段发生了与历史值的实质性改变，卡片边框将自动亮起绿色高亮，并切换展示绿色的“待更新”状态标签。在输入联动过程中，系统会动态校验当前选定的“新快照日期”是否恰好为“上期历史快照日期”的后一天：**仅在日期恰好相差一天（连续记账）时，才触发“累计收益”与“当日收益”的双向自动联动**，以防在不连续的记账断点处发生收益误算。在点击“确认录入”提交时，未填写的字段（保留为空白）会自动智能继承其历史快照的对应值进行记录。
   - **入库规则**：用户确认填写/计算的数据无误后提交，系统将 `total_profit` 和 `daily_profit` 共同落库。
   - **数据修改与保护**：支持对历史收益快照进行二次编辑与删除。在修改时，后端启用“防空覆盖”机制，自动继承原有权属和创建时间，确保底层核心数据不被破坏。
5. **数据可视化分析与偏好模块**
   - **统计图表展示**：在前端引入图表库（如 ECharts 等）。
   - **收益折线图**：展示特定产品的“累计收益走势”与“单日收益走势”。
   - **多区间年化收益对比分析（按需加载与统一计算引擎）**：在“交易流水”标签页后新开独立的“年化分析”标签页，与全局纵览中的“年化收益走势（多区间对比）”统一由后端 `InvAnalysisService` 作为唯一计算引擎，消除了重复代码与口径分歧。全面废弃僵化的过去 12 滚动周期（周/月年化），转由用户手动选定时间区间，支持自主添加多个对比阶段：
     - **用户自主定义多区间与交互**：
       - 前端支持灵活添加、删除多个时间区间卡片（通过 Flatpickr 日历控件精确选择起止日期），允许针对不同时期（如加仓期、持仓期、不同市场行情周期）进行横向对照。系统**完全不强制预设任何死板的默认假数据区间**，初始进入展示清爽的空白指引，支持随时全部清空或自由增减；用户主动点击“添加对比区间”或从走势图点选时才动态生成。
        - **走势图纯点击选区与原生高亮背景联动直达年化对比**：在产品详情与全局纵览的“累计收益走势”折线图中，针对鼠标长按拖拽容易手抖、手势冲突与误触的痛点，**全面取消鼠标按住框选/拖拽操作，升级为纯点击模式**。用户只需在走势图中分别单击两个日期点（第 1 点定起点、第 2 点定终点），即可精准确立对比区间；同时**完美保留框选模式的半透明高亮背景与边界线视觉效果**——底层通过 ECharts `dispatchAction({ type: 'brush', areas: [...] })` 主动渲染原生半透明选区色带，并在确立起点后支持随鼠标悬浮移动平滑动态拉伸预览高亮范围，点击第 2 点即刻锁定选区。底层接入 ZRender 全坐标系事件捕获（基于 `convertFromPixel` 计算 X 轴日期并结合悬浮 Tooltip 状态双重兜底），支持垂直虚线整列及任意高度空白处极速点选，彻底消除瞄准小数据点的繁琐；选区锁定后自适应滑出毛玻璃操作栏，并自动发起异步计算实时展示当前对比各产品在该区间的实际年化收益率预览徽章（支持加载占位动画与防竞态控制），支持一键“👉 带入年化并查看”或“➕ 仅加入对比”，实现看走势、圈波段、算年化的极致闭环体验。
        - **走势图背景区间投影（ECharts markArea）与色彩联动**：针对走势图与已选对比区间存在视觉割裂、无法立刻定位的问题，在走势图控制台新增“区间背景投影”开关按钮。点击后系统通过 ECharts markArea 在折线图背景上绘制半透明竖向高亮色带并在顶部标注“阶段1”、“阶段2”等小标签；内置 6 套柔和区分度调色板（天蓝、翠绿、暖橙、紫罗兰、玫瑰红、青蓝），使图表背景投影与下方胶囊徽章实现 1 对 1 色彩映射，再次点击即可平滑隐藏；当对比区间增删改时自动响应式刷新。
       - **走势图下方已选对比区间看板与快捷管理**：在“累计收益走势”折线图正下方新增集成“已选对比区间”展示与控制台。以轻量级胶囊卡片（Chips）实时呈现当前已保存的所有对比阶段（展示阶段名称、起止日期、相隔天数及快速移除按钮），支持就地清空、快捷发起新圈选与一键直达年化分析对比，彻底解决切换标签页前无法掌握已选区间全貌的痛点。
       - 单产品详情页以优雅的柱状对比图展示同一产品在不同时间段的年化收益率。
       - 全局纵览页以并排分组柱状图展示用户所选的多个产品在各个自定义时间区间下的横向表现对比。
     - **区间首尾相减计算算法（精准透明与人为调优）**：
       - *核心计算公式*：针对每个选定区间 $[startDate, endDate]$，算法定位起止快照点，计算累计收益增量 $\Delta Profit = endProfit - startProfit$，结合期初本金 $principal$ 与两笔快照真实的自然日天数差 $actualDays$，按年化公式折算：
         $$\text{年化收益率} = \frac{\Delta Profit}{principal} \times \frac{365}{actualDays} \times 100\%$$
       - *智能快照就近匹配*：针对非连续记账、节假日断更等情况，起始日期优先就近匹配 $\le startDate$ 的最近一笔有效快照（若无则兜底查找 $\ge startDate$ 的首笔）；结束日期优先匹配 $\le endDate$ 的最近一笔有效快照。
       - *真实天数差核验与除零保护*：以起止快照真实的记录日期计算相隔天数 $actualDays$；若 $actualDays \le 0$ 或起止为同一笔快照、或期初本金 $\le 0$，安全返回 `null`。
       - *彻底解决赎回跳水与断层痛点*：用户通过人为划分时间区间（例如：赎回前一个区间、赎回后一个区间），彻底避开中途赎回导致的跨期累计收益断崖下跌，使年化计算逻辑极度清晰、直观透明且 100% 可自主复核。
       - *高精度与口径一致性*：后端全流程使用 `BigDecimal` 保留 2 位小数，Tooltip 交互中同步展示起止快照匹配日期、相隔真实天数、收益差与期初本金明细。`InvProfitSnapshotServiceImpl` 完全委托 `InvAnalysisService`，保证单产品视图与全局纵览视图中的数据口径百分之百一致。
   - **每日万份收益走势**：在产品详情页新增“万份收益”标签页，严格按最新快照日期向前推算连续 30 个自然日，绘制每日万份收益柱状图。结合底槽阴影、针对性打叉（`✖`）标记以及极简的 X 轴排版，彻底解决日期断层与 0/null 视觉难辨的体验痛点。
   - **全局纵览与多产品对比**：在侧边栏提供独立的“纵览分析”视图，支持通过复选框随意勾选多个产品，并在同屏内直接横向比对它们的“累计收益走势”、“多区间年化收益对比”以及“万份收益走势”。其中累计收益走势图与万份收益走势图均集成了 ECharts `dataZoom` 数据区域缩放（累计收益走势默认聚焦展示最近 100 天，万份收益走势默认聚焦展示最近 30 天，均支持底栏独立滑块平移与缩放，不拦截页面鼠标滚轮），并在万份收益走势中提供右上角 `toolbox` 工具栏（支持一键在柱状图与折线图之间无缝切换），从根本上避免了多产品/长跨度海量数据下走势与柱体被压缩变形的视觉体验问题。
   - **用户级偏好持久化存储（`sys_user_preference`）**：系统引入轻量级的用户偏好配置功能，实现“千人千面”的操作记忆。如在全局纵览中勾选对比的产品状态（`overviewSelectedProductIds`）、全局纵览自定义对比区间（`overviewAnnualIntervals`）以及单产品专属自定义区间（`productAnnualIntervals_{productId}`）均自动静默异步提交至后台偏好库绑定用户，换机登录或刷新页面后无缝自动回显，彻底免去重复配置区间的繁琐。
